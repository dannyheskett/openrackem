# App Store assets

Artwork and listing copy for the iOS App Store, mirroring `android/play-assets/`
for Google Play. Nothing here is compiled into the app — the in-bundle app icon
lives in the asset catalog (`ios/Assets.xcassets`), not in this folder.

## Required

| Asset | Size | Notes |
| --- | --- | --- |
| `icon-1024.png` | 1024x1024 | **No alpha channel, no transparency, no rounded corners.** Apple masks the corners itself; a submitted icon with an alpha channel is rejected outright. sRGB, flattened. Generated by `scripts/gen_store_assets.py` (it writes the opaque RGB copy into the asset catalog; this is that same file). |
| `screenshots/iphone-6.9/` | 1290x2796 | Required. 1-10 images, portrait. Covers every current iPhone; Apple scales this set down for older devices, so no other iPhone size is needed. |

openrackem ships **iPhone only** (`UIDeviceFamily = [1]` in `ios/Info.plist`), so
no iPad screenshots are needed. iPads can still install and run it scaled. If
iPad is ever declared, add `2` to `UIDeviceFamily`, set `UIRequiresFullScreen`
to opt out of Split View, and add a `screenshots/ipad-13/` set at 2064x2752 —
Apple requires that set whenever iPad is supported.

Screenshots must be PNG or JPEG, sRGB, with no alpha channel. They are ordered
in the listing by filename, hence the `01-`/`02-` prefixes.

## Generating screenshots

```bash
make store-shots-ios      # -> screenshots/iphone-6.9/ at native 1290x2796
```

`scripts/gen_store_shots.c` stages four deterministic scenes (fixed seed, scripted
actions) and `TakeScreenshot`s each one. The target runs it under xvfb at the
native App Store size and then strips the alpha channel, which raylib's
screenshots carry and which Apple rejects. A bare `make store-shots` still writes
the 540x960 Play set to `build/store-shots/`.

Note this renders through the **raylib** backend, not the Metal backend the iOS
app actually ships. That is faithful for layout and text — both backends share
`render.c` and, since the Nunito port, the same font and the same `fontSize*0.05`
tracking — but it is worth re-checking against a Simulator capture
(`xcrun simctl io <udid> screenshot`, pinned to an iPhone 16 Pro Max for a native
1290x2796) if anything about the two renderers diverges.
